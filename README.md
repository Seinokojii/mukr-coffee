# МУКР Кофе — бонусная карта

Бонусная программа кофейни МУКР: у каждого ученика своя регистрация, карта и личный QR-код.

- **10 баллов** за любой стакан (маленький 140 сом, большой 170 сом)
- **60 баллов** — бесплатный кофе на выбор, баллы списываются
- баллы хранятся на сервере, а не в телефоне

Сайт: https://mukrcoffee.62-113-109-193.sslip.io (старый адрес https://seinokojii.github.io/mukr-coffee/ сам переводит сюда)

## Как устроено

`server.py` — один файл на стандартной библиотеке Python и SQLite: API (`/api/...`) и сами страницы (`index.html`, `app.css`, `app.js`).
Стоит на VPS за Caddy (служба `site15-mukrcoffee`, порт 8036). Копия на GitHub Pages только перенаправляет: на общем адресе
`*.github.io` у всех проектов один `localStorage`, и токен кассы там мог бы прочитать чужой скрипт.

**Ученик:** регистрируется по телефону → видит карту с оттисками (нажатие переворачивает — сзади личный QR) → выбирает
кофе и жмёт «Заказать» → показывает QR на кассе. Баллы приходят только после того, как бариста отсканировал QR и выдал кофе;
оттиск появляется на карте сам.

**Бариста:** сканирует QR камерой, USB-сканером или вводит 8-значный код → открывается панель ученика: заказы к выдаче
(«Наличными · выдать» / «Картой · выдать») и продажа на кассе без заказа. Отменить можно только свою продажу на кассе в течение
10 минут; заказы и бесплатный кофе отменяет администрация.

**Администрация:** выручка (наличные / карта и QR), касса, ученики (поиск, новый пароль, отключение), заказы, сотрудники, настройки цен.

## Оплата

| PAY_MODE | Как |
|---|---|
| `desk` (сейчас) | ученик заказывает в телефоне, платит на кассе; бариста отмечает наличные или карту |
| `demo` | то же, но продажи помечаются демо и не входят в выручку |
| ключи GoPay в `/etc/site15/mukr-coffee.env` | добавляется оплата по QR банка (ELQR), режим включится сам |

## Нагрузка и защита

Проверено `tools/seed.py` + `tools/load.py` на 10 000 учениках, серверу дано одно ядро (ядро VPS примерно такое же):

| Сценарий | 95% ответов | 99% ответов | Обрывы | Память |
|---|---|---|---|---|
| 500 одновременно, как в жизни | 2,0 мс | 5,7 мс | 0 | 66 МБ |
| 1000 одновременно, как в жизни | 1,9 мс | 4,3 мс | 0 | 82 МБ |
| 500 без пауз (атака) | 179 мс | 280 мс | 0 | 83 МБ |

- пул из 32 потоков; ожидающие соединения лежат в epoll и потоки не занимают (slowloris не работает);
- тело запроса — целиком за 5 с и не больше 20 КБ; Caddy принимает тело сам (`request_buffers`) и режет больше 32 КБ;
- лимиты: по сессии, по адресу (IPv6 — по /64), неверные пароли — по «логин + адрес»; проверка пароля — не больше двух разом;
- в базе — хеши токенов, PBKDF2 паролей; сессия кассы — 14 дней; CSP, HSTS, запрет встраивания;
- копия базы раз в сутки в `data/backups` (14 штук).

Сильный DDoS по сети (гигабиты трафика) один VPS не выдержит никаким кодом — для этого нужен свой домен и Cloudflare перед сервером.

## Команды

```bash
python3 server.py --staff <логин> "<Имя>" [пароль]   # завести бариста
python3 server.py --admin <логин> "<Имя>" [пароль]   # завести администратора
python3 server.py --reset <телефон|логин> [пароль]    # сменить забытый пароль
python3 -m unittest discover -s tests                 # тесты
./publish.sh                                          # выкладка на VPS (база data/ не трогается)
```
